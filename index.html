The spec

One token. Everything
a verifier needs to know.

The Agent Credential Format (ACF) is a signed JWT carried in the x-agent-passport header. Every field was chosen to solve a real documented incident. Nothing invented.

FieldTypeWhat it solves
org + org_domainstringWho owns this agent — domain-verified, not self-asserted. Enables org-level rate limiting and attribution.
agent_idstringWhich specific agent sent this. Stable across token refreshes. The root of every audit trail.
scopesstring[]What it's permitted to do. OAuth 2.0 convention. Verifier rejects anything outside the list.
rulesobjectblockActions[], maxSpendUsd, maxCallsPerRun. The control layer — enforced by the credential, not agent code.
delegation.humanPrincipalstringWhich human authorized this agent. Required for EU AI Act compliance. Enables traceback to a human decision.
delegation.chainstring[]Full chain from root to this agent. Prevents sub-agents from inheriting more scope than their parent.
revocation_idstringKill switch. Revoke this agent in <500ms without waiting for TTL expiry. No redeploy.
expunix tsMax TTL 24h — short TTLs enforced to limit blast radius of a compromised token.

Why it matters

The questions your on-call
engineer is already asking.

"An agent sent 400 emails to customers. Nobody told it to."

Without a permissions layer, agents act within the full scope of their credentials. A blockActions: ["send:email"] rule in the credential stops this before it starts — enforced by the verifier, not the agent's code.

scope overreach
"Security won't approve prod deployment without an audit trail."

Security teams aren't blocking agents because they fear AI. They're blocking them because there's nothing to show an auditor. An immutable log of agent actions, tied to a verified org identity, unblocks this review.

compliance block
"Something's hammering our database and we don't know which agent."

IP-based attribution fails when one org runs hundreds of agents across different IPs. org and agent_id in every request means you can trace any call to its source in one query.

attribution failure
"Agent A spawned Agent B and Agent B called an API we never approved."

No standard today defines what happens when an agent spawns a sub-agent. The delegation.chain field enforces that sub-agents can never exceed their parent's scope — cryptographically, not via prompts.

How it works

30 minutes from zero
to verified agents.

01
Register your org — verify your domain

DNS TXT record. Get an Ed25519 keypair. Your signing key stays yours — we never hold it. The discovery doc publishes your public key at /.well-known/agentpassport.json.

02
Issue a passport when you spawn an agent

Call ap.issue({ agentId, scopes, rules, ttl }). Get back a signed ACF token. Attach it to the agent's outgoing header. One line.

03
APIs verify in one line — offline, under 1ms

Install the verify package. Call verify(token). Full typed payload back: org, agentId, scopes, rules. No network round trip. No database lookup.

04
Revoke or update rules without redeploying

Call rules.revoke('agent-id') or rules.block({ action: 'send:email' }). Propagates in under 500ms. No restart. No redeploy. The kill switch actually works.

verify.ts — what an API receives 
// npm install agentpassport
import { verify } from 'agentpassport'

async function agentAuth(req, res, next) {
  const passport = await verify(req.headers['x-agent-passport'])

  // passport.org         → 'acme_corp'   (domain-verified)
  // passport.agentId     → 'research-agent-01'
  // passport.scopes      → ['read:crm']
  // passport.rules       → { blockActions: ['send:email'] }
  // passport.delegation  → { humanPrincipal: 'user:jane@acme.com' }

  if (!passport.scopes.includes(requiredScope)) {
    return res.status(403).json({ error: 'Scope not granted' })
  }

  req.agent = passport; next()
}
Compatibility

Complements what already
exists. Doesn't replace it.

AgentPassport fills the gaps that MCP and A2A explicitly leave open in their 2026 roadmaps. It's designed to work alongside them, not against them.

MCP
complementary

MCP's 2026 roadmap lists audit trails, enterprise auth, and delegation chains as unaddressed. ACF fills exactly those gaps. An ACF token travels as a header on any MCP request without touching the MCP spec.

A2A (Agent2Agent)
complementary

A2A AgentCards declare authentication requirements. ACF is the runtime credential that backs those declarations. A2A's roadmap calls for formalizing authorization in AgentCards — ACF is that mechanism.

OAuth 2.1
built on top of

ACF tokens are OAuth 2.1-compatible JWTs. The scopes field follows OAuth 2.0 convention. Issuers can use the client credentials flow to issue ACF tokens. No divergence from OAuth, just additions.

Any framework
framework-agnostic

LangChain, CrewAI, LlamaIndex, AutoGen, raw OpenAI — the credential format is the same regardless of how the agent was built. One verify() call, any stack.
