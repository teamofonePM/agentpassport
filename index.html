Why a new spec

Existing standards
leave this gap open.

MCP's own roadmap flags this. A2A's roadmap flags this. The gap is acknowledged — just not yet filled. ACF is a proposal to fill it, openly.

StandardWhat it coversWhat ACF adds
MCPAgent-to-tool communication protocolRuntime identity, scoped permissions, audit, delegation chains — all on MCP's own roadmap as unaddressed
A2AAgent-to-agent communicationEnforcement of AgentCard auth claims at runtime — A2A roadmap calls for this explicitly
OAuth 2.1Human and service authorizationAgent-specific claims: rules, delegation chain, org — ACF tokens are OAuth 2.1-compatible JWTs
What this solves

Real incidents the
spec was built around.

Every field in the ACF spec traces back to a documented problem. Nothing invented.

Fintech · Series B
"An agent sent 400 emails. Nobody told it to."

No scope separation. Agent inherited full credentials. block_actions in the credential would have stopped it — enforced by the verifier, not agent code.

missing: rules.block_actions
Healthcare SaaS · Security team
"We can't ship agents to prod without an audit trail."

84% of orgs can't pass a compliance audit on agent behavior. Verifiable org identity and a tamper-proof action log are what security teams need to say yes.

missing: identity + audit
DevOps startup · AWS bill
"A DevOps agent created recursive clusters. $12k."

No spend cap. No kill switch. Discovered via invoice. max_spend_usd enforced at the credential level — the agent's code doesn't need to know.

missing: rules.max_spend_usd
Multi-agent pipeline · YC W25
"Agent A spawned Agent B. Agent B called an API we never approved."

No standard covers agent-spawns-agent today. delegation.chain cryptographically enforces that sub-agents can't exceed their parent's scope.

missing: delegation.chain
Reference implementation

How an implementation
would work.

01
Org registers and gets a signing keypair

DNS TXT verification. Ed25519 keypair. Signing key stays with the org — never transmitted. Discovery doc at /.well-known/acf.json.

02
Credential issued when agent is spawned

Call acf.issue() with agentId, scopes, and rules. Signed JWT returned. Attached to x-acf-token header.

03
Any API verifies offline in under 1ms

Call verify(token). Full typed payload back — org, agentId, scopes, rules. No network round trip. Cached public key lookup.

04
Rules update without redeploying agents

rules.revoke() or rules.block() propagates in under 500ms. No restart. No redeploy needed.

import { ACF } from 'acf-token'

const acf = new ACF({
  orgId:      'acme_corp',
  orgDomain:  'acme.com',
  signingKey: process.env.ACF_PRIVATE_KEY
})

const { token } = await acf.issue({
  agentId: 'research-agent-01',
  scopes:  ['read:crm'],
  rules:   { blockActions: ['send:email'] },
  ttl:     '1h'
})

headers['x-acf-token'] = token
import { verify } from 'acf-token'

const cred = await verify(
  req.headers['x-acf-token']
)

// cred.org       -> 'acme_corp'
// cred.agentId   -> 'research-agent-01'
// cred.scopes    -> ['read:crm']
// cred.rules     -> { blockActions: [...] }

if (!cred.scopes.includes(scope)) {
  return res.status(403).json({ error: 'denied' })
}
// offline · under 1ms · no round trip
import { RulesClient } from 'acf-token'

const rules = new RulesClient(process.env.ACF_KEY)

// Kill one agent instantly
await rules.revoke('research-agent-01')

// Block an action across all org agents
await rules.block({ action: 'send:external-email' })

// Propagates in under 500ms. No redeploy.
